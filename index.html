Control de Versiones

El historial inteligente de tu código

📌 1.1 Definición de control de versiones

El control de versiones es un sistema que registra y gestiona todos los cambios que se hacen en los archivos de un proyecto a lo largo del tiempo. Es como el historial de Word, pero mucho más poderoso: guarda quién hizo qué cambio, cuándo lo hizo, por qué lo hizo y permite regresar a cualquier versión anterior si algo sale mal.

Sin control de versiones, trabajarías guardando copias como proyecto_final.zip, proyecto_final2.zip, proyecto_final_AHORA_SI.zip y al final no sabrías cuál es la buena. Con control de versiones, todo queda ordenado y seguro.

📌 1.2 ¿Cuáles son? Explicación de cada uno

🔵 A) Sistemas Locales

El historial vive solo en una computadora. El programador guarda versiones en su propio disco. Ejemplo más simple: copiar la carpeta del proyecto y pegarla con otro nombre. Herramienta clásica: RCS.

🟢 B) Sistemas Centralizados

Hay un servidor central que guarda todo el historial y todos los programadores se conectan a él para bajar y subir cambios. Ejemplos: CVS y Subversion (SVN). Todos dependen de ese servidor.

🟣 C) Sistemas Distribuidos

Cada programador tiene una copia COMPLETA del historial en su computadora, no solo la última versión. Puede trabajar sin internet y luego sincronizar. Ejemplos: Git, Mercurial. Hoy es el estándar mundial.

📌 1.3 Características, ventajas y desventajas de cada una

TipoCaracterísticasVentajasDesventajas
LocalUn solo usuario, sin servidor, sin redMuy simple, no necesita internet, rápido de aprenderSi se daña la PC se pierde todo, no sirve para equipos, fácil equivocarse
CentralizadoServidor central, control de acceso, historial únicoEl administrador controla todo, fácil de entender quién tiene quéSi el servidor falla nadie trabaja, sin internet no puedes guardar, es más lento
DistribuidoCopia completa en cada equipo, ramas, trabajo sin conexiónSe trabaja sin internet, es rapidísimo, se puede experimentar con ramas, casi imposible perder todoAl inicio es más difícil de aprender, ocupa más espacio

📌 1.4 Explica su funcionamiento

Funciona en 4 pasos que se repiten siempre:

  1. Working Directory: donde escribes tu código normal.
  2. Staging Area: con git add eliges qué cambios quieres guardar.
  3. Commit: con git commit -m "mensaje" tomas una foto de tu proyecto con un mensaje que explica qué hiciste.
  4. Repositorio: con git push subes esa foto a GitHub para que tu equipo la vea. Con git pull bajas los cambios de tus compañeros.

Conceptos clave: Repositorio: carpeta con proyecto + historial. Rama (Branch): línea de trabajo paralela para probar algo sin romper lo principal. Merge: unir una rama con otra. Conflicto: cuando dos personas cambian la misma línea y hay que decidir cuál queda.

📌 1.5 Cómo se usa el control de versiones en el rastreo y gestión de cambios

Rastreo: Cada commit guarda fecha, autor, mensaje y exactamente qué líneas cambiaron. Si una app deja de funcionar, puedes ver: "Ah, el lunes Juan cambió esta línea y ahí se rompió". Puedes comparar dos versiones con git diff y ver línea por línea qué cambió.
Gestión: Puedes crear una rama para cada función nueva (rama-login, rama-mapa), probar sin riesgo, y cuando ya funciona, la unes a la rama principal con un Merge. Si algo sale mal, haces git revert o git reset y regresas a la versión que sí funcionaba, sin perder todo el proyecto.

📌 1.6 Ejemplos

git init
git add .
git commit -m "Primera versión de mi app"
git branch nueva-funcion
git checkout nueva-funcion
git push origin main

Ejemplo real: En WhatsApp trabajan 100 programadores. Uno arregla los emojis, otro la cámara y otro los mensajes. Gracias a Git y sus ramas, ninguno borra el trabajo del otro y al final todo se une en una sola app.

Persistencia y Acceso a Datos

Que tus datos no se borren al cerrar la app

📌 2.1 Definición

La persistencia es la capacidad de una aplicación de guardar datos de forma permanente para que sigan existiendo aunque se cierre la app, se apague el celular o se reinicie el dispositivo. Sin persistencia, cada vez que abrieras la app tendrías que volver a escribir tu nombre, tu contraseña y todo de nuevo. Es lo contrario a la memoria temporal (RAM), que se borra al apagar.

📌 2.2 Características

  • Durabilidad: los datos no se pierden.
  • Disponibilidad: se pueden leer en cualquier momento.
  • Consistencia: los datos guardados son los mismos que se leen.
  • Seguridad: se pueden cifrar datos sensibles.
  • Eficiencia: debe guardar y leer rápido sin gastar mucha batería.

📌 2.3 Formas de persistencia en dispositivos móviles

A) Archivos: Se guardan documentos tal cual: fotos, PDF, audios, videos, archivos TXT. En Android se guardan en almacenamiento interno o externo. Ejemplo: cuando descargas una foto de WhatsApp, queda guardada como archivo. Ventaja: simple y bueno para archivos grandes. Desventaja: difícil de buscar y ordenar.

B) Bases de datos locales: Se guardan dentro del celular, no necesitan internet. La más usada es SQLite. Ejemplo: tus contactos, tus notas, tus tareas, el historial de mensajes. Ventaja: funciona sin internet, es rápida y ordenada. Desventaja: si desinstalas la app o cambias de celular, puedes perder los datos si no hay respaldo.

C) Bases de datos remotas mediante servicios web: Los datos se guardan en un servidor en la nube y la app los pide por internet con una API. Ejemplos: Firebase Firestore, MySQL en un servidor, Supabase. Ejemplo: Instagram: tus fotos no están solo en tu celular, están en la nube y las ves en cualquier celular. Ventaja: se comparte entre dispositivos y no se pierde. Desventaja: necesita internet y es más lenta.

📌 2.4 Tipos de datos almacenados en función de las formas de persistencia

FormaTipo de dato que guardaEjemplo
Preferencias (SharedPreferences / DataStore)Datos pequeños de configuraciónIdioma, modo oscuro, si ya vio el tutorial
ArchivosDatos no estructurados, grandesFotos, videos, PDF, audios

Base de datos remotaDatos compartidos en la nubePerfil de Instagram, chats, pedidos de Rappi

📌 2.5 Mecanismos de control de acceso a medios persistentes

A) Biblioteca de clases: Es un conjunto de clases ya programadas que te facilitan guardar y leer datos sin escribir todo desde cero. Ejemplo: en Android, la librería Room te da clases como @Entity, @Dao, @Database para trabajar la base de datos de forma fácil y segura.

B) Clases de SQLite: Son las clases directas para usar la base de datos SQLite: SQLiteOpenHelper para crear y actualizar la base, y SQLiteDatabase para ejecutar INSERT, SELECT, UPDATE, DELETE. Es más manual pero te da control total. Es la base sobre la que trabaja Room.

C) Mapeo Relacional de Objetos (ORM): Es una técnica que convierte las tablas de la base de datos en objetos de tu código. En vez de escribir SQL a mano, trabajas con objetos. Ejemplo: tienes una tabla usuarios, el ORM te crea un objeto Usuario con usuario.nombre, usuario.correo. Ejemplos de ORM: Room en Android, Hibernate en Java, Entity Framework en C#. Ventaja: escribes menos código y cometes menos errores.

📌 2.6 Proceso de autenticación y consumo de servicios web en aplicaciones móviles

  1. El usuario escribe correo y contraseña en la app.
  2. La app envía esos datos cifrados con HTTPS al servidor (nunca en texto plano).
  3. El servidor verifica en su base de datos si son correctos.
  4. Si son correctos, el servidor responde con un TOKEN (una llave digital, como un pase VIP) y datos en formato JSON.
  5. La app guarda ese token de forma segura.
  6. En cada petición siguiente, la app manda el token en el encabezado: Authorization: Bearer TU_TOKEN.
  7. El servidor revisa el token y si es válido, entrega los datos. Si venció, pide volver a iniciar sesión.

Consumo: Se hace con métodos HTTP: GET (pedir datos), POST (crear), PUT (actualizar), DELETE (borrar). Librerías para hacerlo: Retrofit, Volley, HttpURLConnection.

📌 2.7 Ejemplos

// Ejemplo: pedir datos a una API con token
fetch("https://api.ejemplo.com/usuarios", {
  headers: { "Authorization": "Bearer TU_TOKEN" }
})
// Ejemplo SQL en SQLite
SELECT * FROM notas WHERE favorita = 1;

Ejemplo real: Abres Instagram y no escribes tu contraseña cada vez. Instagram guardó tu token y así sabe que eres tú en cualquier celular.

Gestión de Sensores

Tu celular siente el mundo

📌 3.1 Definición de sensores

Un sensor es un componente físico (hardware) del celular que detecta una condición del mundo real (movimiento, luz, ubicación, temperatura, huella) y la convierte en una señal eléctrica o dato digital que la aplicación puede leer y usar. Sin sensores, tu celular sería solo una pantalla: no sabría si lo giras, dónde estás o si hay poca luz.

📌 3.2 Tipos de sensores en dispositivos móviles

1. Sensores de movimiento: Acelerómetro: detecta aceleración y movimiento, sirve para girar pantalla, contar pasos, detectar choques. Giroscopio: detecta rotación precisa, se usa en juegos y realidad aumentada. Podómetro: cuenta pasos.

2. Sensores ambientales: Luz: ajusta el brillo de la pantalla. Proximidad: apaga la pantalla cuando te acercas el celular en una llamada. Temperatura, Humedad y Presión barométrica: apps de clima y salud.

3. Sensores de posición: GPS: ubicación exacta con satélites, usado en Maps, Uber, Rappi. Magnetómetro / Brújula: sabe hacia dónde apuntas el celular. Sensor de orientación: combina varios sensores para saber la posición del celular.

4. Sensores biométricos y otros: Huella dactilar y Reconocimiento facial: desbloqueo seguro. Ritmo cardíaco y Oxígeno: relojes y apps de salud. Micrófono y Cámara: también son sensores: detectan sonido e imagen.

📌 3.3 Proceso de gestión de sensores: habilitación, obtención y procesamiento de información

Paso 1 - Habilitación: La app debe pedir permiso al usuario. Ejemplo: "¿Permitir que esta app acceda a tu ubicación?". En Android se hace con permisos en AndroidManifest.xml y en tiempo de ejecución. Si el usuario dice que no, la app no puede usar ese sensor. También se debe verificar si el celular tiene ese sensor, porque no todos tienen todos.

Paso 2 - Obtención de datos: Se registra un "escuchador" (SensorEventListener) que recibe los datos del sensor cada cierto tiempo. Los datos llegan crudos, como números: Acelerómetro: X=0.5, Y=1.2, Z=9.8. GPS: Latitud 19.43, Longitud -99.13. Se debe elegir la velocidad de muestreo: rápida para juegos, lenta para ahorrar batería.

Paso 3 - Procesamiento de información: La app convierte esos números en algo útil. Ejemplos: Si el acelerómetro detecta muchos movimientos rítmicos = estás caminando, suma un paso. Si el sensor de luz dice que hay poca luz = sube el brillo. Si el GPS dice que te moviste 100 metros = actualiza el mapa. Después se muestra el resultado al usuario y se apaga el sensor cuando ya no se necesita para ahorrar batería.

Ejemplo completo: App de contar pasos: Habilita acelerómetro → Obtiene datos cada 100ms → Procesa: si hay un pico de movimiento = 1 paso → Muestra "Llevas 1,200 pasos".

Mueve tu celular y presiona el botón...

Uso de Recursos Multimedia

Imágenes, audio, video y animaciones

📌 4.1 Definición

Los recursos multimedia son todos los elementos visuales y auditivos que hacen que una app sea atractiva, interactiva y fácil de entender: imágenes, audios, videos, animaciones y elementos visuales dinámicos. Sin multimedia, una app sería solo texto aburrido. Con multimedia, una app se siente viva, profesional y divertida.

📌 4.2 Tipos de recursos multimedia aplicables a la programación móvil

Imágenes: Fotos, iconos, fondos, logos. Formatos: JPG (fotos), PNG (con transparencia), WEBP (pesa menos, ideal para móvil). Ejemplo: foto de perfil, icono de WhatsApp.

Audio: Música, efectos de sonido, notificaciones, notas de voz. Formatos: MP3, WAV, OGG. Ejemplo: sonido de mensaje, música de Spotify.

Video: Tutoriales, reels, anuncios, clases. Formato: MP4. Ejemplo: videos de TikTok, YouTube.

Animaciones: Movimientos que hacen la app más viva. Formatos: GIF, Lottie (animaciones vectoriales ligeras), animaciones XML. Ejemplo: corazón que late en Instagram, pantalla de carga que gira.

Elementos visuales dinámicos: Elementos que cambian según lo que hace el usuario: botones que cambian de color, gráficas que se mueven, mapas interactivos, carruseles de fotos.

📌 4.3 Elementos de la estructura de proyectos donde se almacenan los recursos multimedia

En Android (Android Studio): res/drawable/ → imágenes e iconos. res/raw/ → audio y video. res/anim/ → animaciones XML. assets/ → archivos que se leen tal cual.

En Flutter: carpeta assets/images/ y assets/audios/, y se declaran en pubspec.yaml.

En React Native / Web: carpeta assets/ o public/. Regla de oro: Siempre optimizar: las imágenes deben estar en varias resoluciones (mdpi, hdpi, xhdpi) y comprimidas para que la app no pese mucho ni gaste datos.

📌 4.4 Componentes de software en el uso de recursos multimedia de aplicaciones móviles

ImageView: componente para mostrar imágenes en pantalla. VideoView y ExoPlayer: para reproducir video. ExoPlayer es el profesional usado por YouTube, soporta streaming y calidad adaptable. MediaPlayer y SoundPool: para audio. MediaPlayer para canciones largas, SoundPool para sonidos cortos como un clic. CameraX / Camera2: para tomar fotos y video desde la app. Glide y Picasso: librerías que bajan imágenes de internet, las recortan, las optimizan y las guardan en caché para que carguen rápido.

Servicios y Notificaciones

Tu app trabajando aunque no la veas

📌 5.1 Definición

Un servicio es un componente de la app que realiza tareas en segundo plano sin necesidad de que el usuario tenga la app abierta ni vea una pantalla. Las notificaciones son los avisos que el sistema muestra al usuario para informarle que algo pasó, aunque la app esté cerrada. Juntos hacen que la app se sienta viva: te avisa, descarga, sube y sincroniza sin que tú hagas nada.

📌 5.2 Qué son las tareas en segundo plano en aplicaciones móviles

Son tareas que se ejecutan mientras usas otra app o tienes el celular bloqueado. Ejemplos: Reproducir música en Spotify aunque estés en WhatsApp, Descargar una película mientras haces otra cosa, Subir tus fotos a Google Fotos automáticamente, Rastrear tu ubicación mientras corres con Strava, Sincronizar mensajes de WhatsApp aunque no tengas la app abierta. En Android se hacen con Service, WorkManager y JobScheduler. WorkManager es el recomendado hoy porque aunque apagues el celular, al prenderlo sigue la tarea.

📌 5.3 Tratamiento de notificaciones en aplicaciones móviles

El tratamiento es todo el ciclo de vida de una notificación:

  1. Permiso: La app pide permiso: "¿Quieres recibir notificaciones?"
  2. Creación: Se crea la notificación con título, mensaje, icono y canal (en Android 8+ se usan canales: mensajes, promociones, etc.)
  3. Envío: Puede ser Local (la crea la misma app, Ej: "¡Toma agua!") o Push / Remota (viene de un servidor por internet, Ej: "Juan te envió un mensaje").
  4. Visualización: El sistema la muestra en la barra, pantalla de bloqueo o como burbuja.
  5. Interacción: El usuario la toca y la app se abre en la pantalla correcta, o la desliza para borrarla, o le da a "Responder" sin abrir la app.

📌 5.4 Proceso de implementación de: proveedores de contenido, tareas en segundo plano y notificaciones

A) Proveedores de contenido (Content Providers): Son componentes que permiten compartir datos entre apps de forma segura y ordenada. Ejemplo: tu app de contactos le comparte tus contactos a WhatsApp sin que WhatsApp entre directo a tu base de datos. Se implementa creando una clase que hereda de ContentProvider y definiendo una URI como content://com.ejemplo.contactos. Otras apps piden datos con ContentResolver.

B) Tareas en segundo plano: Se implementa creando un Service o un Worker de WorkManager. Se define qué tarea hará, cuándo (cada 1 hora, solo con WiFi, solo cargando) y qué pasa si falla. Ejemplo: WorkManager sube tus fotos solo cuando tienes WiFi.

C) Notificaciones: Se implementa creando un canal de notificación, luego un NotificationCompat.Builder con título, texto e icono, y se lanza con NotificationManager. Para notificaciones Push, se usa Firebase Cloud Messaging (FCM): el servidor manda el mensaje a Firebase, Firebase lo manda al celular y el celular lo muestra.

📌 5.5 Servicios de cómputo en la nube aplicables a la programación de aplicaciones móviles

El cómputo en la nube es usar computadoras y servicios de Google, Amazon o Microsoft por internet para que hagan el trabajo pesado en vez de tu celular. Aplicaciones en móvil:

  • Almacenamiento: Google Drive, Firebase Storage para fotos y archivos.
  • Base de datos en la nube: Firebase Firestore, Supabase, AWS DynamoDB.
  • Autenticación: Login con Google, Facebook, correo con Firebase Auth.
  • Notificaciones: Firebase Cloud Messaging (FCM).
  • Inteligencia Artificial: Reconocer fotos, traducir, chatbots con Google Cloud AI.
  • Hosting y Funciones: Firebase Hosting y Cloud Functions para correr código sin servidor propio.

Ventajas: No necesitas comprar un servidor, pagas solo lo que usas, funciona para millones de usuarios, es más seguro y siempre está disponible. Ejemplos: Firebase, AWS (Amazon Web Services), Google Cloud Platform, Microsoft Azure.

Librerías y Toolkits para Desarrollo Móvil

No reinventes la rueda, úsala

📌 6.1 Qué es una librería y qué es un toolkit

Librería: Es un conjunto de funciones, clases y código ya hecho que tú puedes usar cuando quieras para resolver un problema específico. Tú tienes el control: tú decides cuándo llamarla. Es como un libro de recetas: tú eliges qué receta usar. Ejemplo: quieres hacer una gráfica bonita, usas la librería MPAndroidChart solo para eso.

Toolkit: Es una caja de herramientas completa que incluye librerías, herramientas, documentación, emuladores y una estructura para construir algo completo. También se le llama SDK (Software Development Kit) o Framework. El toolkit te da las reglas y la estructura: tú sigues su forma de trabajar. Es como una cocina completa ya equipada: ya trae estufa, ollas, recetas y todo. Ejemplo: Flutter, Android SDK, React Native, Xcode.

Depuración y Seguridad

Encuentra errores y protege tu app

📌 7.1 Qué es la depuración y seguridad

Depuración (Debug): Es el proceso de buscar, identificar y corregir errores (bugs) en el código de una aplicación. Un bug puede ser que un botón no funcione, que la app se cierre de golpe (crash) o que un número salga mal. Depurar es como ser detective: revisas pistas, pruebas paso a paso y arreglas el problema.

Seguridad: Es el conjunto de medidas para proteger los datos del usuario y la app de ataques, robos y accesos no autorizados. En móvil es vital porque el celular guarda fotos, contraseñas, ubicación, tarjetas y mensajes. Una app insegura puede robar todo eso.

📌 7.2 Herramientas de depuración incluidas en el entorno de desarrollo móvil

1. Logcat: Ventana en Android Studio que muestra todo lo que pasa en tu app en tiempo real como un chat. Los errores salen en rojo, las advertencias en amarillo. Con Log.d("MI_APP", "Aquí llegó") puedes dejar mensajes para ver por dónde va tu código.

2. Breakpoints (Puntos de interrupción): Pones un punto rojo en una línea y la app se pausa ahí. Puedes ver cuánto vale cada variable en ese momento y avanzar línea por línea con Step Over / Step Into. Es la herramienta más poderosa para entender por qué algo falla.

3. Emulador: Un celular virtual dentro de tu computadora para probar tu app sin tener un celular físico. Puedes probar en diferentes marcas, tamaños y versiones de Android.

4. Android Profiler: Herramienta que mide en tiempo real cuánta CPU, memoria, batería y datos de internet usa tu app. Si tu app gasta mucha batería, aquí lo descubres.

5. Layout Inspector / Inspector de diseño: Te muestra cómo está construida tu pantalla capa por capa para ver por qué un botón quedó chueco, tapado o fuera de la pantalla.

6. App Inspection / Database Inspector: Te deja ver y editar la base de datos de tu app en vivo sin tener que abrir archivos.

📌 7.3 Seguridad en aplicaciones móviles - Buenas prácticas

  • Nunca guardes contraseñas en texto plano. Siempre cifradas con hash.
  • Usa siempre HTTPS, nunca HTTP, para que nadie espíe los datos.
  • Pide solo los permisos que necesitas. Si tu app es de notas, no pidas cámara ni ubicación.
  • Cifra datos sensibles como tarjetas, ubicación y mensajes.
  • No guardes claves secretas o tokens en el código. Guárdalos en lugares seguros.
  • Actualiza tus librerías. Las viejas tienen agujeros de seguridad que los hackers ya conocen.
  • Usa autenticación segura: token + huella / cara.
  • Valida todo lo que escribe el usuario para evitar inyecciones SQL.

📌 7.4 Amenazas comunes y Referencias

Amenazas: Robo de datos, apps falsas que roban contraseñas, WiFi público sin protección, permisos abusivos, código desactualizado. Para prevenirlas existe OWASP Mobile Top 10, la lista oficial de los 10 errores de seguridad más peligrosos en móvil.
